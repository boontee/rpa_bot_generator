# Iterative Bot Generation Plan

## Top-Level Overview

**Goal:** Define a reusable, iterative process for generating IBM RPA WAL bot scripts using the `ibm-rpa` skill. Rather than producing a complete script in one shot, the process generates the script **incrementally** — one validated slice at a time — and uses the IBM RPA Studio log (via the `mcp__rpa-studio-log__read_studio_log` MCP tool) to detect and fix parse errors before advancing to the next slice. Each iteration ends only when Studio opens the current slice without errors.

**Scope:** This plan describes the *workflow* (process, tooling, and checkpoints), not a specific bot. A placeholder "Hello World" web-login stub is used only to illustrate the loop.

**Non-Goals:**
- Does not automate the user's Studio interaction — Studio open/save is always a manual step.
- Does not add new tools or MCP servers.

---

## Workflow Overview

```
┌─────────────────────────────────────────────────────────────────┐
│  ITERATION N                                                     │
│                                                                  │
│  1. Determine next slice  (sub-task scope)                       │
│  2. Validate commands     (commands_kb.md + wal-reference.md)    │
│  3. Write / append .wal.txt                                      │
│  4. Run wal_generator.py  → binary .wal                          │
│  5. User opens .wal in Studio                                    │
│  6. Read Studio log       (MCP tool)                             │
│  7a. Errors?  → diagnose → fix .wal.txt → go to step 4          │
│  7b. Clean?   → confirm with user → advance to iteration N+1    │
└─────────────────────────────────────────────────────────────────┘
```

### Sub-Task 2 — Design the Script Skeleton (Iteration 0)

**Intent:** Before writing any logic, produce the minimal valid WAL structure: all `defVar` declarations, the main-flow `goSub` list, and empty `beginSub … endSub` stubs for every subroutine. This skeleton must open in Studio without errors before any logic is added.

**Expected Outcomes:**
- `<bot_name>.wal.txt` exists and contains only `defVar` lines, `goSub` calls, and stub subroutines with entry/exit `logMessage` lines and `onError --label ErrorHandler`.
- `<bot_name>.wal` binary is generated by `wal_generator.py`.
- Studio opens the file with **no ERROR lines** in the log (background `Variable.Parse(null)` WARN is expected and ignored).

**Todo List:**
- [ ] Identify all process inputs/outputs and declare them as `defVar` lines (correct `--type` per `commands_kb.md`).
- [ ] List all subroutines: `Init`, one per logical phase, `ErrorHandler`, `Cleanup`.
- [ ] Write skeleton `.wal.txt` — main flow is `goSub` calls only; every `beginSub` body contains only entry/exit `logMessage` stubs and `onError --label ErrorHandler`.
- [ ] Validate every command in the skeleton against `commands_kb.md` (no hallucinated commands).
- [ ] Run `py tools/wal_generator.py --template template/template.wal --script <name>.wal.txt --output <name>.wal`.
- [ ] Instruct the user: **File → New Script → Source tab → Paste the `.wal.txt` content → Save** (or open the generated `.wal` directly if using option B).
- [ ] Read Studio log via `mcp__rpa-studio-log__read_studio_log`. If ERROR lines exist, apply fix and re-run generator; repeat until clean.
- [ ] Update plan with confirmed variable list and subroutine names for use in subsequent iterations.

**Relevant Context:**
- `SKILL.md` §"Mandatory Script Structure" — exact layout rule
- `SKILL.md` §"Fixing Script Errors" — log-reading protocol
- `tools/wal_generator.py` — binary `.wal` producer
- `template/template.wal` — protobuf template required by generator
- MCP tool: `mcp__rpa-studio-log__read_studio_log` — reads Studio log tail; highlights ERROR/Exception lines

**Status:** [ ] pending

### Sub-Task 3 — Implement Subroutines Incrementally (One Subroutine Per Iteration)

**Intent:** Fill in **one subroutine per iteration** with real commands. After each subroutine is implemented and the `.wal` is regenerated, the user opens it in Studio and the log is checked before proceeding to the next subroutine. This is the core iterative loop. If the same subroutine fails to parse after **3 consecutive fix attempts**, the loop pauses and the user is asked to inspect the log manually before continuing.

**Expected Outcomes (per iteration):**
- The target subroutine contains all intended commands with correct syntax.
- Every command is validated against `commands_kb.md` before writing.
- The generated `.wal` opens in Studio with no new ERROR lines.
- The user confirms the iteration is clean before the next subroutine is started.

**Todo List (one complete pass = one subroutine):**
- [ ] Identify the next subroutine to implement (follow the order: `Init` → core phases in declaration order → `ErrorHandler` → `Cleanup`).
- [ ] For each command to be added: look up the exact action name, parameter names, and output variable name in `commands_kb.md`; if not found, find the valid alternative — do not use unlisted commands.
- [ ] Apply the pre-output checklist from `SKILL.md` to the new subroutine section only.
- [ ] Append or replace the subroutine body in `.wal.txt` using `apply_diff` or `search_and_replace` (never `write_file` on `.wal`).
- [ ] Run `py tools/wal_generator.py --template template/template.wal --script <name>.wal.txt --output <name>.wal` to regenerate the binary.
- [ ] Prompt user: open `<name>.wal` in Studio and confirm it loaded (or report any error dialog).
- [ ] Call `mcp__rpa-studio-log__read_studio_log` to read the latest log tail.
  - If **no ERROR lines**: confirm iteration complete with user; mark this subroutine done; proceed to the next subroutine.
  - If **ERROR/Exception lines present** (attempt 1 or 2): classify the error (see error table in `SKILL.md §Fixing Script Errors`); apply the minimal fix to `.wal.txt`; regenerate; re-read log; increment attempt counter.
  - If **ERROR/Exception lines still present on attempt 3**: **pause** — do not attempt a 4th automated fix. Tell the user: "Three fix attempts have not resolved the parse error. Please inspect `Studio.log` directly (path: `C:\Users\Administrator\AppData\Local\IBM Robotic Process Automation\Studio.log`) and paste any lines you think are relevant. I will wait for your input before continuing."
- [ ] Reset the fix-attempt counter to 0 when moving to the next subroutine.
- [ ] After all subroutines are implemented, run a final full pre-output checklist pass over the complete `.wal.txt`.

**Relevant Context:**
- `SKILL.md` §"Confirmed Invalid Commands & Common Syntax Traps" — do-not-use list
- `SKILL.md` §"Pre-Output Checklist" — full validation checklist
- `SKILL.md` §"Fixing Script Errors" §Step 2 "Classify the error" table — maps log patterns to fixes
- `commands_kb.md` — must be consulted for every command before use
- `wal-reference.md` — condensed syntax reference for quick cross-checks
- `tools/wal_generator.py` — must be re-run after every `.wal.txt` change
- MCP tool: `mcp__rpa-studio-log__read_studio_log` — primary error detection instrument

### Sub-Task 4 — Final Validation and Handover

**Intent:** After all subroutines pass individually, do one final end-to-end validation: run the complete script through the pre-output checklist, regenerate the binary, confirm Studio opens cleanly, and hand over the artefacts to the user.

**Expected Outcomes:**
- All items on the `SKILL.md` pre-output checklist pass (no unchecked items).
- The final `<bot_name>.wal` opens in Studio with no ERROR lines.
- The user has both `<bot_name>.wal.txt` (editable source) and `<bot_name>.wal` (Studio-ready binary).
- Any known limitations, assumptions, or selector fragility points are documented in a comment block at the top of `.wal.txt`.

**Todo List:**
- [ ] Read the complete `.wal.txt` and run every item on the `SKILL.md` pre-output checklist.
- [ ] Fix any remaining checklist violations in `.wal.txt`.
- [ ] Regenerate binary: `py tools/wal_generator.py --template template/template.wal --script <name>.wal.txt --output <name>.wal`.
- [ ] Prompt user to open the final `.wal` in Studio.
- [ ] Read Studio log via `mcp__rpa-studio-log__read_studio_log`; confirm no ERROR lines.
- [ ] Write a brief summary comment block at the top of `.wal.txt`: assumptions, input variables, subroutine map, known limitations.
- [ ] Present the user with the final artefact paths and instructions for deploying to IBM RPA Control Center if applicable.

**Relevant Context:**
- `SKILL.md` §"Pre-Output Checklist" — master checklist
- `conventions.md` — naming / structure standards for final review
- `tools/wal_generator.py` — final binary generation
- MCP tool: `mcp__rpa-studio-log__read_studio_log` — final log confirmation

**Status:** [ ] pending

## Iteration Loop Summary

| Phase | Action | Tool / Artefact |
|---|---|---|
| 0 | Activate skill, gather requirements | `use_skill ibm-rpa`, user Q&A |
| 0 | Write skeleton `.wal.txt` | `write_file` (`.wal.txt` only) |
| 0 | Generate binary | `wal_generator.py` |
| 0 | User opens in Studio | Manual Studio step |
| 0 | Read log | `mcp__rpa-studio-log__read_studio_log` |
| 0 | Fix if needed | `apply_diff` / `search_and_replace` on `.wal.txt` → regenerate |
| N | Implement next subroutine body | `apply_diff` / `search_and_replace` on `.wal.txt` |
| N | Validate commands | `commands_kb.md` + `wal-reference.md` lookup |
| N | Regenerate binary | `wal_generator.py` |
| N | User opens in Studio | Manual Studio step |
| N | Read log | `mcp__rpa-studio-log__read_studio_log` |
| N | Fix if errors | Classify error → minimal fix → regenerate → re-read log |
| Final | Full checklist pass | `SKILL.md §Pre-Output Checklist` |
| Final | Handover | `.wal.txt` + `.wal` artefacts |

## Key Constraints

- **Never write `.wal` directly** — always write `.wal.txt` then run `wal_generator.py`.
- **Never use `write_file` on an existing `.wal`** — use `apply_diff` or `search_and_replace` on `.wal.txt`, then regenerate.
- **Every command must exist in `commands_kb.md`** before use — no exceptions.
- **Log must be read after every Studio open** — do not advance to the next subroutine until the log is confirmed clean.
- **Background `Variable.Parse(null)` WARN is not an error** — ignore it when no ERROR lines are present.
- **Do not hardcode credentials** — use `getAsset` or process variables.
